# Участие в проекте

Для сообщения об ошибке не нужно знать Swift: создайте [обращение](https://github.com/eugggeneee/journal/issues/new/choose), опишите шаги, ожидаемый и фактический результат. Укажите модель iPhone, iOS и версию Journal. Перед публикацией скриншота скройте личные заметки.

Для кода создайте ветку от актуального `main` и откройте pull request. Одна задача — одно понятное изменение. Объясните, какое действие пользователя исправляется и как проверили результат. Дождитесь проверок iOS; не публикуйте приложения с секретами, чужими сертификатами и реальными резервными копиями.

Инструкции сборки — в [DEVELOPMENT.md](docs/DEVELOPMENT.md), правила выпусков — в [RELEASING.md](docs/RELEASING.md). Для изменений правил добавляйте тест на наблюдаемое поведение, особенно для дат, лимитов, парсера и восстановления данных. Не добавляйте тесты, просто повторяющие структуру кода.

Следуйте системным паттернам iOS. Не добавляйте веб-оболочку, аналитику, аккаунты и сетевые сервисы без отдельного обсуждения изменения продукта. Предложения функций приветствуются в Issues.

## Описание действий в Git и GitHub

Каждый коммит, pull request, аннотированный тег, выпуск и описание другого изменяющего действия оформляйте подробно и по существу, на русском, в прошедшем времени. Используйте подходящие разделы: **Сделано / Добавлено / Переделано / Убрано / Исправлено / Проверено**. Пустые разделы пропускайте. В заголовке называйте конкретный результат, например: «Исправлено: сохранение оценок после перезапуска».

В описании укажите, что изменено и зачем, какие файлы или сценарии затронуты, как проверено поведение и что ещё требует проверки. Для создания ветки, слияния, push и изменения настроек репозитория укажите фактическое действие и его цель в том же формате. Не заменяйте подробности общими словами вроде «улучшения» и не отмечайте невыполненные проверки успешными. Передавайте многострочные сообщения через файл (`git commit -F`, `gh pr create --body-file`); опубликованную историю ради оформления не переписывайте.

Пример сообщения коммита:

```text
Исправлено: восстановление оценок после перезапуска

Исправлено:
- Записи сохраняются до обновления интерфейса, чтобы сбой записи не показывал несохранённую оценку.

Проверено:
- Интеграционный тест повторного открытия хранилища восстановил добавленную оценку.
```

Вклад распространяется по лицензии MIT проекта. Общайтесь уважительно и по существу.
