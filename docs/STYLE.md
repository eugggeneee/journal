# Правила кода и интерфейса

## Интерфейс

- Только Material 3: компоненты пакета `material_ui`. Cupertino-виджеты и переходы не используются.
- Цвета берутся из `ColorScheme` темы. Статусы: отметки, пропуски и лимиты строятся функциями из `ui/kit/foundation/journal_theme.dart` (пастельные заливки Material и контрастные подписи одного назначения во всех разделах). Произвольные HEX-цвета в экранах запрещены.
- Размеры и отступы кратны 2, основные шаги 4, 8, 12, 16, 24.
- Скругления: крупные карточки 32, карточки списка 28 (крайние) и 6 (внутренние), кнопки и фильтры stadium.
- Одинаковые по смыслу экраны строятся из одних компонентов. Новый элемент сначала ищется в `ui/kit`, а если нужен второй раз, выносится туда.
- Текст интерфейса на русском, без эмодзи. Учебная запись — «отметка», комментарий к паре — «пометка», вычисляемый показатель — «средний балл». Склонения через `plural` из `core/dates.dart`.
- Любое действие, меняющее данные, отменяется через `showUndo`, подтверждающие диалоги не добавляются, кроме необратимых.
- Размер карточек не должен меняться от появления плашек и значков.
- Поверхности плоские: тени, `elevation`, затемнение и подъём не используются; разделение задают цвета и границы.
- Любое действие занимает не больше трёх шагов; значения по умолчанию подставляются заранее.
- Шапки: вкладки через `LargePage`, вложенные экраны через `SubHeader`.
- Размеры едины: главные карточки 32, карточки списка 28, поля и вложенные панели 24, плашки и чипы 20 и меньше; пиктограмма 24 в подложке 44 с радиусом 14, у группы 38 в подложке 64; главная кнопка 52, остальные не ниже 48; текстовые кнопки 48.
- Текст не обрезается многоточием: он переносится, а в шапках и узких плашках уменьшается.
- Строки настроек и списков устроены одинаково (`BadgeRow`), у каждой свой оттенок (`hueTone`).
- На вводных экранах общий список карточек прокручивается при нехватке места, нижние кнопки остаются доступными.
- Доступность: у интерактивных элементов `Semantics` или `tooltip`, контраст текста по `ColorScheme`, поддержка отключённых анимаций.

## Анимации

- Длительности и кривые только из `Motion` (`short` 220 мс, `medium` 320 мс, `long` 480 мс, `page` 420 мс или `Motion.ms(n)`; кривые `standard`, `decelerate`, `accelerate`, `emphasized`, `spring`, `release`; `elasticOut`, `easeOutBack` и другие отскоки не используются). Готовых `Duration(milliseconds: ...)` в экранах нет: иначе настройка «Анимации» их не затронет.
- Появление элемента списка: `Appear` (каскад) или `Reveal` (новая запись). Смена содержимого: `Smooth`, `PopIn`, `AnimatedNumber`, `FadeInSlivers`.
- Кривая `spring` выходит за 1: для прозрачности и вложенных кривых значение ограничивается через `.clamped`.
- Нажатие карточки: `PressScale`. Вибрация только через `Haptics`.
- Анимации не двигают соседние элементы скачком и учитывают системную настройку отключения анимаций и настройку «Анимации».

## Код

- Dart: `flutter analyze` без новых замечаний. Форматирование как в существующем коде; массовый `dart format` не применяется, чтобы не шуметь в diff.
- Имена файлов `snake_case.dart`; один основной публичный виджет или класс на файл, мелкие приватные рядом.
- Слои и запреты импортов: [ARCHITECTURE.md](ARCHITECTURE.md). Импорты внутри проекта относительные, в тестах `package:journal/...`.
- Логика без Flutter-виджетов лежит в `logic` и покрывается тестами.
- Комментарии на русском, только по существу: зачем, а не что. Закомментированный код и TODO в основную ветку не попадают.
- Нет устаревших веток совместимости: если формат данных меняется, делается миграция, а старый код удаляется.

## Файлы и репозиторий

- Кодировка UTF-8, переводы строк LF, файл заканчивается переводом строки (`.editorconfig`).
- Нет эмодзи в коде, документации, workflow и сообщениях коммитов.
- Документация краткая и фактическая: что, как, зачем; без маркетинга и повторов.
- Секреты, ключи, `pubspec.lock`, сборочные папки и платформенные папки в репозиторий не добавляются.
- Бинарные ресурсы только нужные для сборки; в README светлый нативный экспорт (`docs/logo.png`).
- Перед сдачей: `python3 scripts/project/check.py` без ошибок.

Пиктограммы и их подложки используют общий тон темы. Семантический цвет данных сохраняется у шкал и подписей. Основное начертание заголовков и выделений задаёт JournalType.

Иконки и постеры берут роли цветов из `AppTheme`. После изменения палитры обновите экспорт командой `flutter test --dart-define=EXPORT_ARTWORK_PALETTES=true test/project/artwork_palette_test.dart`. На iOS объём колокольчика задают плоскости Icon Composer и системное освещение.
