# Правила кода и интерфейса

## Интерфейс

- Только Material 3: компоненты пакета `material_ui`. Cupertino-виджеты и переходы не используются.
- Цвета берутся из `ColorScheme` темы. Статусы: оценки, пропуски и лимиты строятся функциями из `ui/kit/foundation/ctx.dart` (тональные схемы Material от Red 500, Green 500, Amber 500). Произвольные HEX-цвета в экранах запрещены.
- Размеры и отступы кратны 2, основные шаги 4, 8, 12, 16, 24.
- Скругления: крупные карточки 32, карточки списка 28 (крайние) и 6 (внутренние), кнопки и фильтры stadium.
- Одинаковые по смыслу экраны строятся из одних компонентов. Новый элемент сначала ищется в `ui/kit`, а если нужен второй раз, выносится туда.
- Текст интерфейса на русском, без эмодзи. Склонения через `plural` из `core/dates.dart`.
- Любое действие, меняющее данные, отменяется через `showUndo`, подтверждающие диалоги не добавляются, кроме необратимых.
- Размер карточек не должен меняться от появления плашек и значков.
- Доступность: у интерактивных элементов `Semantics` или `tooltip`, контраст текста по `ColorScheme`, поддержка отключённых анимаций.

## Анимации

- Длительности и кривые только из `Motion` (`short` 220 мс, `medium` 320 мс, `long` 480 мс; кривые `standard`, `emphasized`, `spring`).
- Появление элемента списка: `Appear` (каскад) или `Reveal` (новая запись). Смена содержимого: `Smooth`, `PopIn`, `AnimatedNumber`, `FadeInSlivers`.
- Нажатие карточки: `PressScale`. Вибрация только через `Haptics`.
- Анимации не двигают соседние элементы скачком и учитывают системную настройку отключения анимаций.

## Код

- Dart: `flutter analyze` без новых замечаний. Форматирование как в существующем коде; массовый `dart format` не применяется, чтобы не шуметь в diff.
- Имена файлов `snake_case.dart`; один основной публичный виджет или класс на файл, мелкие приватные рядом.
- Слои и запреты импортов: [ARCHITECTURE.md](ARCHITECTURE.md). Импорты внутри проекта относительные, в тестах `package:journal/...`.
- Логика без Flutter-виджетов лежит в `logic` и покрывается тестами.
- Комментарии на русском, только по существу: зачем, а не что. Закомментированный код и TODO в основную ветку не попадают.
- Нет устаревших веток совместимости: если формат данных меняется, делается миграция, а старый код удаляется.

## Файлы и репозиторий

- Кодировка UTF-8, переводы строк LF, файл заканчивается переводом строки (`.editorconfig`).
- Нет эмодзи в коде, документации, workflow и сообщениях коммитов.
- Документация краткая и фактическая: что, как, зачем; без маркетинга и повторов.
- Секреты, ключи, `pubspec.lock`, сборочные папки и платформенные папки в репозиторий не добавляются.
- Бинарные ресурсы только нужные для сборки и README.
- После изменений в `lib/` и `test/` обновляется `docs/GRAPH.md`.
