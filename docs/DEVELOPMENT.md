# Разработка

## Требования

- Xcode 26.3 на поддерживаемой версии macOS; SDK iOS 26.2.
- Swift 6, целевая версия приложения iOS 18.0, только iPhone.
- Python 3 для обновления Xcode-проекта. Сторонних зависимостей приложения и генератора проекта нет.

Откройте `Journal.xcodeproj`, выберите схему **Journal** и симулятор iPhone. Для установки напрямую из Xcode выберите свой Team; настройки чужой подписи в репозиторий не сохраняйте.

Разработка исходников возможна на Windows, но сборка SwiftUI выполняется в Xcode. Готовый IPA собирает GitHub Actions; локальная установка Xcode на Windows не требуется и не поддерживается.

## Структура

| Путь | Назначение |
|---|---|
| `App/` | SwiftUI, формы, навигация, адаптивный интерфейс, хранилище приложения |
| `Sources/JournalCore/` | Чистая логика: календарь, сущности, звонки, лимиты, HTML, сеть и резервные копии |
| `Tests/JournalCoreTests/` | Swift Testing и вымышленный HTML в реальном формате колледжа |
| `UITests/` | Проверки основных экранов, ввода, отмены, крупного текста и ориентации |
| `AppTests/` | Проверка настоящего хранилища: перезапуск, ошибка записи, восстановление повреждённого файла |
| `App/Resources/` | Иконка, системный акцент и privacy manifest |
| `scripts/` | Генерация проекта, проверки, упаковка и проверка IPA |
| `version.json` | Единый источник номера выпуска, marketing version и build number |

## Команды

```sh
swift test --parallel
python3 scripts/generate_project.py
git diff --exit-code -- Journal.xcodeproj
bash scripts/test-ios.sh
bash scripts/package-ipa.sh
```

`test-ios.sh` сначала собирает UI-тесты, затем запускает их на доступных симуляторах iOS 26+ и iOS 18. При отсутствии нужного runtime проверка завершается ошибкой: отсутствие проверки не выдаётся за успех.

`package-ipa.sh` создаёт настоящий device archive без подписи, кладёт приложение в `Payload/Journal.app`, проверяет содержимое IPA и считает SHA-256. AltStore выполняет персональную подпись при установке пользователем.

После добавления или удаления Swift-файлов в `App/`, `AppTests/` и `UITests/` запустите генератор и закоммитьте Xcode-проект. Файлы пакета `JournalCore` SwiftPM обнаруживает самостоятельно. Генератор детерминированный: повторный запуск не меняет проект.

## Хранение

`Application Support/Journal/journal.json` содержит состояние формата v3. Перед публикацией изменения кодируется и атомарно записывается новое состояние; только после успеха обновляется UI. Предыдущая рабочая версия — `previous.json`. Повреждённые исходники сохраняются как `damaged-UUID.json`.

Резервная копия содержит настройки и все коллекции, включая расписание. Импорт проверяет идентификатор, версию, настройки и отдельные записи. Нечитаемые и повторные записи считаются и показываются до подтверждения. Ошибка корневого формата не заменяет текущие данные. Максимальный размер импорта — 64 МБ.

Учебные даты моделируются `Day`, а не моментами UTC. Календарь Gregorian, зона Europe/Minsk. UUID задаёт идентичность личной записи; номер пары — идентичность строки в расписании дня. Названия предметов меняются только на уровне отображения, ключ сайта сохраняется.

## Сеть и тестовые данные

`ScheduleClient` получает публичный HTML обычным GET. Эфемерная сессия без cookies и URLCache; перенаправления разрешены только на тот же HTTPS-хост колледжа. Приватные данные не участвуют в URL. Граница ответа — 8 МБ. Сетевые тесты используют внедряемый transport; настоящая сеть не нужна для проверки правил.

Debug-параметр `--demo` запускает вымышленные данные в памяти без сетевых запросов и записи на диск. Он используется для UI-проверок и двух скриншотов README. Release-сборка игнорирует этот параметр.

## Дизайн

Используйте нативные `NavigationStack`, `TabView`, `Form`, `List`, `Menu`, `DatePicker`, системные листы и SF Symbols. Прямые вызовы API iOS 26 защищайте `#available`; на iOS 18 нужен рабочий системный эквивалент. Не превращайте карточки содержимого в стеклянные панели. Учитывайте VoiceOver, Dynamic Type, Reduce Motion, контраст, обе темы и минимальную зону нажатия 44 pt.
