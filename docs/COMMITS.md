# Коммиты

Формат основан на Conventional Commits. Тип и область пишутся латиницей, описание по-русски.

```
тип(область): описание

Необязательное тело: что и почему.

Необязательный подвал.
```

## Заголовок

- До 72 символов, без точки в конце, без эмодзи.
- Повелительное наклонение: «добавить», «исправить», «убрать».
- Область необязательна, но желательна.

## Типы

| Тип | Применение | Влияет на версию |
|---|---|---|
| feat | Новая возможность для пользователя | PATCH или MINOR |
| fix | Исправление ошибки | PATCH |
| perf | Ускорение без смены поведения | PATCH |
| refactor | Внутренняя переработка без смены поведения | нет |
| style | Форматирование кода без смены логики | нет |
| docs | Документация | нет |
| test | Тесты | нет |
| build | Сборка, зависимости, `pubspec.yaml` | нет |
| ci | Workflow и скрипты проверок | нет |
| chore | Служебные изменения, релизный коммит | нет |
| revert | Откат коммита | по откатываемому |

Выбор между PATCH и MINOR для `feat` определяется только [VERSIONING.md](VERSIONING.md), а не типом коммита.

## Области

`schedule`, `grades`, `absences`, `profile`, `settings`, `onboarding`, `kit`, `theme`, `data`, `logic`, `core`, `icons`, `release`, `deps`, `docs`.

## Тело и подвал

- Тело отвечает на вопрос «почему», а не пересказывает diff.
- Несовместимое изменение: подвал `BREAKING CHANGE: описание`.
- Ссылки: `Refs #12`, `Fixes #12`.

## Примеры

```
feat(schedule): показать время перерыва в карточке пары
fix(absences): считать часы по уважительной причине отдельно от лимита
refactor(kit): вынести общие карточки оценок и пропусков в overview
perf(schedule): не пересобирать неделю при смене вкладки
docs: описать порядок выпуска пред-релизов
ci: проверять граф проекта в pull request
chore(release): 1.0.0
revert: feat(schedule): показать время перерыва в карточке пары
```

## Правила

- Один коммит, одно логическое изменение; сборка и тесты проходят на каждом коммите.
- Не смешивать `refactor` и `feat` в одном коммите.
- Изменение файлов в `lib/` или `test/` идёт вместе с обновлённым `docs/GRAPH.md` в том же коммите.
- Изменение поведения идёт вместе со строкой в `CHANGELOG.md` (раздел `[Не выпущено]`).
- Релизный коммит: `chore(release): X.Y.Z`; в нём меняются только версия, CHANGELOG и заметки релиза.
- Опубликованную историю `main` не переписывать.
