# Нумерация версий

Формат: `MAJOR.MINOR.PATCH`, например `1.0.7`. Первая публичная версия: `1.0.0`.

## Правила

| Часть | Когда растёт | Диапазон |
|---|---|---|
| PATCH (последняя цифра) | Любое обычное обновление: исправления, улучшения, небольшие функции | 0-20 |
| MINOR (средняя) | Очень крупное обновление | без ограничения |
| MAJOR (первая) | Только полная переработка или полная замена приложения | от 1 |

- Обычные обновления идут только в последнюю цифру: `1.0.0`, `1.0.1`, ... `1.0.20`.
- Значение PATCH больше 20 запрещено. После `X.Y.20` следующая версия: `X.(Y+1).0`.
- При повышении MINOR PATCH сбрасывается в 0, при повышении MAJOR сбрасываются MINOR и PATCH.
- Версии ниже `1.0.0` не используются. Номера не пропускаются, не переиспользуются и не уменьшаются.

## Что считать очень крупным обновлением (MINOR)

Достаточно одного признака:
- новый раздел приложения уровня вкладки;
- изменение формата данных или резервной копии с миграцией;
- переработка нескольких основных экранов;
- смена способа получения расписания.

Новая отдельная функция, новый экран настроек, правка цветов и анимаций остаются PATCH.

## Что считать полной переработкой (MAJOR)

Приложение пересобрано или заменено целиком: новая архитектура, новый интерфейс, несовместимые данные. Решение принимает владелец проекта, в CHANGELOG описывается причина и путь миграции. На практике MAJOR почти не используется.

## Пред-релизы

`X.Y.Z-beta.N` и `X.Y.Z-rc.N`, где N начинается с 1. Подробности: [PRERELEASES.md](PRERELEASES.md). Порядок: `1.1.0-beta.1` < `1.1.0-beta.2` < `1.1.0-rc.1` < `1.1.0`.

## Номер сборки

В `pubspec.yaml` после `+`: `1.0.0+1`. В CI номер сборки равен номеру запуска workflow и всегда растёт (Android `versionCode`, iOS `CFBundleVersion`). В iOS пред-релизный суффикс в имя версии не попадает: для `1.1.0-beta.1` выставляется `1.1.0`.

## Где хранится версия

| Место | Что |
|---|---|
| `pubspec.yaml`, строка `version` | Единственный источник истины |
| Git-тег | `v` + версия без номера сборки: `v1.0.0` |
| `CHANGELOG.md` | Раздел `## [1.0.0]` для каждой стабильной версии |
| `.github/releases/v1.0.0.md` | Текст релиза для стабильной версии |

Тег должен совпадать с `pubspec.yaml`; workflow останавливается, если это не так.

## Команды

```bash
python3 scripts/project/version.py show          # текущая версия
python3 scripts/project/version.py next          # следующая по правилам
python3 scripts/project/version.py bump patch    # patch | minor | major
python3 scripts/project/version.py check         # проверка pubspec, CHANGELOG, заметок релиза
```

`bump patch` на `X.Y.20` сам выдаёт `X.(Y+1).0`.

## Совместимость данных

- PATCH: данные и резервные копии полностью совместимы в обе стороны.
- MINOR: допускается миграция вперёд; новая версия читает копии всех прежних версий.
- MAJOR: совместимость описывается в CHANGELOG.

Версия формата резервной копии хранится в поле `version` файла копии (сейчас 2) и меняется только вместе с миграцией.
