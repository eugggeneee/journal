# GitHub и выпуски

## Репозиторий

`eugggeneee/journal` — публичный исходный код нового нативного приложения. `journal-old` остаётся отдельным источником истории. Основная ветка — `main`; изменения после начальной настройки идут через короткие ветки и pull request. Слияние — squash, ветка после слияния удаляется. Сайт, Pages, wiki и отдельный GitHub Project не используются.

Правила основной ветки: запрет удаления и force push, pull request, разрешённые обсуждения и успешная проверка `verify-and-build`. Один сопровождающий может слить собственный PR: обязательного чужого одобрения нет. Не ослабляйте проверки для выпуска.

## Actions

Один workflow `.github/workflows/ios.yml`:

- PR в `main`: генерация и сверка проекта, core-тесты, сборка и UI-тесты на iOS 26+ и iOS 18.
- Ручной запуск: те же проверки и упаковка IPA в артефакт. Публичный релиз не создаётся.
- Push тега `v*`: те же проверки, упаковка и публикация GitHub Release после проверки метаданных.

Нет запуска по расписанию и каждого обычного push в ветку. `workflow_dispatch` запускайте только по необходимости. Артефакты проверок хранятся 7 дней; опубликованный IPA — в Releases. Прогоны не требуют Apple Developer secrets или стороннего сервера сборки.

Actions закреплены по SHA. Checkout не сохраняет токен в git-конфигурации. GitHub token используется для публикации только внутри шага выпуска. Не используйте `pull_request_target` для запуска кода из PR. При изменении workflow отдельно проверяйте разрешения и обработку недоверенных данных.

## Новый выпуск

1. В отдельной ветке обновите `version.json`: `release`, числовой `marketing` и возрастающий `build`. Например, `1.0.0-beta.1`, `1.0.0`, `1`.
2. Создайте `docs/releases/v<release>.md` с понятным описанием изменений и проверок.
3. Запустите генератор проекта, проверьте diff и откройте PR. Дождитесь зелёной проверки.
4. После squash-слияния поставьте тег **на проверенный коммит main** и отправьте его:

```sh
git switch main
git pull --ff-only
python3 scripts/check-release.py v1.0.0-beta.1
git tag -a v1.0.0-beta.1 -m 'Journal 1.0.0-beta.1'
git push origin v1.0.0-beta.1
```

Workflow проверит совпадение тега с `version.json`, заново проверит код и приложит `Journal.ipa` и `SHA256SUMS`. Тег с суффиксом `-beta.N` публикуется как prerelease. Существующие теги и файлы опубликованных выпусков не перезаписываются; для исправления нужен новый номер.

Первый тестовый выпуск — `1.0.0-beta.1`. Стабильный `1.0.0` публикуется после проверки владельцем на настоящем iPhone. Симулятор и успешная сборка не подтверждают установку через AltStore.

## Перед публикацией

Проверьте [чеклист](TESTING.md), отсутствие секретов и личных данных, корректность скриншотов, неизменность bundle ID и возможность экспортировать/импортировать данные. Обновите статус выпуска в README. Поддержку iOS 18 нельзя заявлять только по deployment target — проверка runtime обязательна.
