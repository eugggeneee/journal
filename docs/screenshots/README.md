# Галерея Journal для iPhone

[Открыть галерею](https://github.com/eugggeneee/journal/tree/screenshots/pack) · [Скачать ZIP](https://github.com/eugggeneee/journal/archive/refs/heads/screenshots.zip) · [Запустить сборку](https://github.com/eugggeneee/journal/actions/workflows/screenshots.yml)

В GitHub Actions выберите **Пак скриншотов Journal → Run workflow** на ветке `main`. Сценарий найдёт последний стабильный релиз. Если все файлы для этой версии уже готовы, он проверит их SHA-256 и завершится до запуска симулятора. Новый комплект заменяет предыдущий одним коммитом после проверки.

## Что сохранять при каждом выпуске

1. Снимать только iOS. Выбирать самый новый базовый iPhone среди доступных в Xcode. Записывать фактическую модель, версию iOS, разрешение и исходный коммит в `manifest.json`.
2. Использовать вымышленные данные группы **0000**. Снимать основные экраны, формы, листы, настройки и первоначальную настройку в светлой и тёмной темах. Главную снимать в каждом цвете приложения.
3. Для каждого кадра сохранять оригинал в полном разрешении (`-raw.webp`) и два мокапа на прозрачном фоне (`-framed-light.webp` и `-framed-dark.webp`). Цвет корпуса выбирается независимо от темы приложения. Отдельно публиковать оба многоразовых PNG-корпуса с прозрачным окном дисплея в `frames/`.
4. В `mockups/` выпускать минимум три разные композиции с иконкой и названием Journal, цветами приложения и реальными кадрами. Горизонтальная обложка показывает ход дня, вертикальная — расписание, парный макет — оценки и пропуски. Перед публикацией нового оформления проверить читаемость текста, края экрана, прозрачность и вырез камеры в обоих корпусах.

Оригиналы хранятся в `ios/light/` и `ios/dark/`. Съёмка использует `simctl io screenshot` и приложение из стабильного тега. Фиксированные часы и тестовое расписание подставляются только в отдельную сборку для галереи. Фотореалистичные корпуса — студийные макеты, подготовленные для Journal.
