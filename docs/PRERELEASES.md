# Тестовые версии

Тестовая версия проверяется на реальных устройствах до стабильного релиза. Обязательна перед каждым MINOR и MAJOR, для PATCH по желанию.

## Обозначения

| Тип | Версия и тег | Смысл |
|---|---|---|
| beta | `1.1.0-beta.1`, `v1.1.0-beta.1` | Функции готовы, возможны ошибки |
| rc | `1.1.0-rc.1`, `v1.1.0-rc.1` | Кандидат в релиз: допускаются только исправления |

Нумерация N начинается с 1 для каждой целевой версии и растёт: `beta.1`, `beta.2`, `rc.1`, `rc.2`. Тег пред-релиза не переиспользуется и не перемещается; исправление выходит под следующим номером.

## Что делает workflow

- Тег с суффиксом `-beta.N` или `-rc.N` публикуется как pre-release и не становится «последним» релизом.
- Раздел в `CHANGELOG.md` и файл `.github/releases/` не требуются. Описание берётся из `.github/releases/<тег>.md`, если файл есть, иначе из заголовков коммитов.
- Android: имя версии с суффиксом, подпись тем же ключом, что и стабильные версии.
- iOS: имя версии без суффикса (требование `CFBundleShortVersionString`), номер сборки растёт.

## Порядок выпуска

1. Выставить версию в `pubspec.yaml` вручную: `version: 1.1.0-beta.1+1`.
2. Выполнить проверки: `python3 scripts/project/check.py`, `flutter analyze`, `flutter test`.
3. Закоммитить: `chore(release): 1.1.0-beta.1`.
4. Поставить тег и отправить:
   ```bash
   git tag v1.1.0-beta.1
   git push origin main v1.1.0-beta.1
   ```
5. Передать тестировщикам ссылку на релиз. Установка и проверка файлов: как в [RELEASING.md](RELEASING.md).
6. Собирать замечания в issues с меткой `beta`, указывая версию тестовой сборки.
7. Исправления выпускать как `beta.2`, `beta.3`; после стабилизации перейти на `rc.1`.

## Выход в стабильную версию

1. Все issues с меткой `beta` для этой версии закрыты или явно отложены.
2. `rc` без новых замечаний не менее суток.
3. Поднять версию без суффикса: `version: 1.1.0+1`.
4. Оформить CHANGELOG и `.github/releases/v1.1.0.md`.
5. Коммит `chore(release): 1.1.0`, тег `v1.1.0` по [RELEASING.md](RELEASING.md).

## Чек-лист проверки тестовой сборки

- Первый запуск и выбор группы; повторный запуск.
- Обновление поверх предыдущей версии: данные сохранились.
- Расписание: загрузка, офлайн, смена даты, время звонков, пометки.
- Оценки: добавление, правка, удаление, отмена, «Ещё одну».
- Пропуски: отметка у пары, «Весь день», смена причины, лимиты и предупреждения.
- Резервная копия: сохранить и восстановить.
- Светлая и тёмная темы, смена цветовой темы, смена значка.
- Планшет или широкий экран, крупный шрифт системы.
- Отключённые анимации в системе.

## Откат

Тестовую версию, которая не прошла проверку, не удалять: выпустить следующий номер. Пользователи стабильной ветки пред-релизы не получают.
