# Инструкции для автоматических помощников

Обязательны для любого автоматического инструмента и ИИ-ассистента, меняющего репозиторий. Это единая точка входа: она связывает остальные правила и перечисляет действия, которые нельзя пропускать.

## Перед работой: прочитать полностью

Читать целиком, а не выборочно. Незнание правил не оправдывает их нарушение.

| Документ | Когда |
|---|---|
| `AGENTS.md`, `CONTRIBUTING.md` | всегда |
| `docs/ARCHITECTURE.md` | всегда: структура, слои, данные |
| `docs/STYLE.md` | всегда: правила кода, интерфейса и анимаций |
| `docs/COMMITS.md` | всегда: формат коммитов |
| `docs/VERSIONING.md` | всегда: когда и как меняется версия |
| `docs/TESTING.md` | всегда: какие проверки и тесты нужны |
| `docs/PRERELEASES.md`, `docs/RELEASING.md` | при выпуске беты или релиза |
| `SECURITY.md` | при работе с данными, сетью и ключами |

## Обязательные действия

1. После каждого изменения выполнить `python3 scripts/project/check.py`, затем `flutter analyze` и `flutter test`. Ошибки исправлять, а не обходить.
2. Изменение поведения для пользователя отразить в `CHANGELOG.md`, раздел `[Не выпущено]`.
3. Логику в `lib/logic` и `lib/data` менять вместе с тестами; исправление ошибки начинать с теста, который её воспроизводит.
4. Новые общие элементы интерфейса добавлять в `lib/ui/kit`; длительности и кривые анимаций брать только из `Motion`; цвета из темы.
5. Версию менять только в релизном коммите или при выпуске пред-релиза, по `docs/VERSIONING.md` (последняя цифра 0-20, затем средняя).
6. Коммиты оформлять по `docs/COMMITS.md`: один коммит, одно логическое изменение.
7. Менялась структура папок, правила или команды: обновить `docs/ARCHITECTURE.md` и связанные документы в том же коммите.
8. Перед сдачей работы убрать всё лишнее: неиспользуемые файлы, закомментированный код, TODO, `__pycache__`, `.idea`, `.dart_tool`, `build`, `pubspec.lock`, `.metadata`, `*.iml`. Проверка: `python3 scripts/project/check.py`.

## Запрещено

- Эмодзи, секреты, ключи, платформенные папки (`android/`, `ios/`), сборочные артефакты.
- Обход проверок и правил слоёв из `docs/ARCHITECTURE.md`.
- Переписывание опубликованной истории `main` и перемещение тегов.
